# Chat UI Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A local chat-style web app (`ideate ui`) for ideation-loop, with live streaming of every agent, background runs that survive the browser and the server, and steering from a message box.

**Architecture:** Runs stay CLI processes ("workers") that now stream agent text to `runs/<id>/live.jsonl`, keep a heartbeat in `worker.json`, and read queued owner input from `inbox.jsonl`. A small `node:http` server lists ideas, spawns workers, appends to inboxes and tails `live.jsonl`/`state.json` over SSE. A React + Vite front end renders ideas as chat conversations derived from `state.json` plus the live log.

**Tech Stack:** Node ≥ 20, TypeScript (strict, ESM, NodeNext), zod, `@inquirer/prompts` (existing); new: react 18.3.1, react-dom 18.3.1, react-markdown 9.0.1, remark-gfm 4.0.0, vite 5.4.11, @vitejs/plugin-react 4.3.4, @types/react 18.3.12, @types/react-dom 18.3.1 (all exact pins). Tests: `node --import tsx --test`.

**Spec:** `docs/superpowers/specs/2026-11-13-chat-ui-design.md`

## Global Constraints

- Server binds `127.0.0.1` only; default port `4317`; `--port`, `--no-open`.
- Never lose a run or written output when the browser closes or `ideate ui` stops (spec anti-goal).
- Existing runs without `live.jsonl`, `worker.json`, `maxRounds` or `inboxConsumed` must load and render from `state.json` alone.
- CLI flags, behaviour and exit codes stay backward compatible; all existing tests keep passing.
- One process per idea: `continue`/`resume` refuse when the idea is active.
- No runtime CDNs or network calls from the UI; bundle all assets.
- Dependencies pinned to the exact versions above (`--save-exact`).
- `live.jsonl` event shapes: `{"t":"call_start","call":n,"provider","role","round","ts"}`, `{"t":"delta","call":n,"text"}`, `{"t":"call_end","call":n,"ok":bool,"ms":n,"error"?,"ts"}`.
- `worker.json` = `{ pid, startedAt, heartbeatAt, command }`, heartbeat every 5 s.
- Inbox item types: `note`, `add_scenario`, `edit_scenario`, `remove_scenario`, `reopen`, `more`.
- `npm run build` must produce `dist/cli.js` and `dist/ui/index.html`; `npm link` users get the UI.

## Review Focus

1. **A worker writing `live.jsonl` while the server reads it** — the last line may be half-written; replay must stop at the last newline and pick the rest up next time, never emit a broken or duplicated event. (Task 2 test `readLive ignores a partial trailing line`.)
2. **Two tabs, or a reconnect, on the same idea** — each SSE client replays from its own offset; no duplicated or skipped text. (Task 6 test `live replay resumes from offset without duplicates`.)
3. **`state.json` read while the worker is replacing it** — a parse failure must be skipped and retried on the next poll, not crash the server or send an empty idea. (Task 6 test `state poll survives an unreadable state.json`.)
4. **Empty or whitespace-only brief / message, and a very large pasted brief (200 KB)** — empty is rejected with 400 and nothing is spawned; large briefs go through stdin as today. (Task 6 test `POST /api/ideas rejects empty brief`; Task 9 manual check with a 200 KB paste.)
5. **An old run (no live log, no worker file, `continuedAt: true`)** — renders a full conversation and is neither "active" nor "interrupted" unless its status is `running`. (Task 5 test `old runs are not active`, Task 7 test `buildConversation renders a legacy run`.)

  - `POST /api/ideas/:id/stop` → 409 if not active, else `process.kill(pid, "SIGTERM")`.
  - `PATCH /api/ideas/:id` `{ title }` → 409 if active (title edits wait until the run is idle; UI disables rename while active), else load/save state.
  - `GET /api/ideas/:id/report` → `text/markdown` from `renderReport`.
  - Anything else under `/api` → 404; other paths serve `dist/ui` files with `index.html` fallback; if `dist/ui` is missing, `/` returns a page saying "Run npm run build".
